# Verify Network Isolation

Verify that the Ubuntu VM has working internet connectivity and that the optional host-level firewall restrictions behave as intended.

## Verify Network Connectivity

Inside the VM, check its IPv4 configuration:

```bash
ip -4 addr
ip -4 route
```

With UTM's Emulated VLAN networking, the VM should receive its network configuration through DHCP.

Verify DNS resolution:

```bash
getent ahostsv4 example.com
```

Verify outbound HTTPS connectivity:

```bash
curl -4 -I --connect-timeout 5 https://example.com
```

A successful HTTP response confirms that DNS resolution and outbound HTTPS connectivity are working.

## Verify Network Restrictions

If LuLu is configured, verify that the VM cannot establish connections to internal services that should be blocked.

Use a known, authorized test endpoint on your local network. For example, replace `<test-ip>` and `<test-port>` with the address and port of a service you control:

```bash
nc -4 -vz -w 3 <test-ip> <test-port>
```

Run the same test from the macOS host to confirm that the endpoint is reachable without the VM restrictions.

The expected result is:

- **Host:** Connection succeeds.
- **VM:** Connection is blocked or times out.

> [!IMPORTANT]
> A failed connection alone does not prove that LuLu blocked it. Verify that the test endpoint is reachable from the host and inspect LuLu's logs or connection alerts to confirm the restriction.

Repeat the test for any additional private network ranges that are relevant to your environment.

## Verify VPN Routing (Optional)

If the host uses a VPN, compare the public IPv4 addresses reported by the host and the VM.

On both systems, run:

```bash
curl -4 --max-time 10 https://api.ipify.org
echo
```

If the VM's traffic is routed through the host's VPN, both systems should normally report the same public IPv4 address.

> [!NOTE]
> Matching public IP addresses do not independently prove that VPN routing is enforced or that traffic cannot bypass the VPN.

## Disable IPv6

The host firewall rules documented in this guide restrict IPv4 address ranges but do not provide equivalent IPv6 restrictions.

Since IPv6 is not required for this development environment, disable automatic IPv6 configuration inside the Ubuntu VM.

The Ubuntu Server installer may enable DHCPv6 by default. Update the Netplan configuration to disable DHCPv6, IPv6 Router Advertisements, and link-local addressing:

Choose the command corresponding to your Ubuntu version:

| Ubuntu version | Command |
|---|---|
| **24.04 LTS** | `sudo sed -i '/dhcp4: true/a\      dhcp6: false\n      accept-ra: false\n      link-local: []'  /etc/netplan/50-cloud-init.yaml` |
| **26.04 LTS** | `sudo sed -i -e 's/dhcp6: true/dhcp6: false/' -e '/dhcp6: false/a\      accept-ra: false\n      link-local: []' /etc/netplan/00-installer-config.yaml` |

Validate and apply the configuration:

```bash
sudo netplan generate
sudo netplan try
```

Confirm the changes when prompted, then reboot the VM:

```bash
sudo reboot
```

After reconnecting via SSH, verify that no IPv6 addresses or routes are configured:

```bash
ip -6 addr
ip -6 route
```

Both commands should produce no output.

> [!NOTE]
> This configuration disables automatic IPv6 addressing and routing, not the IPv6 protocol itself. It assumes the default Netplan file generated by the Ubuntu Server installer. It does not replace host-level network restrictions.
